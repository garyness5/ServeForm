Savveyra v0.1.71 – ContactList Refactor

Completed
---------
• Refactored ContactList JS into a single clean contactSave object.
• Standardized Save, Save & New, Edit, Duplicate, Delete, Cancel and Status workflows.
• Removed duplicate deleteContact() procedures.
• Moved Edit workflow into JS object.
• Moved Delete workflow into JS object.
• Standardized modal handling.

Duplicate
---------
• duplicate_contact_master rewritten.
• Duplicate creates a new Contact record only.
• Customer/Venue relationships are intentionally NOT duplicated.
• New Contact receives:
    - new ID
    - " - Copy" suffix
    - copied Contact fields
    - original Active state
• Duplicate opens immediately in Edit mode.

Delete
------
• Converted to standard soft delete.
• deleted = true
• active = false
• updated_at maintained.
• Delete confirmation modal standardized.
• Delete button disabled while delete query is executing.
• Cancel disabled during delete execution.
• Main Delete button disabled when no row is selected.

Buttons
-------
Standardized button behaviour:
• Edit disabled without selection.
• Duplicate disabled without selection.
• Delete disabled without selection.
• Confirmation Delete disabled while query executes.

General cleanup
---------------
• Removed duplicate JS procedures.
• Consistent Contact naming/messages.
• Reset widget behaviour standardized.
• Store cleanup after Save/Delete standardized.
• ContactList now follows the same implementation pattern as VenueList.

Business rules confirmed
------------------------
• Contact relationships belong to Customer/Venue ownership.
• Contact duplication does not duplicate Customer or Venue links.
• ContactList is not responsible for editing Customer/Venue relationships.
• ContactList displays relationships only.
• Contacts remain linked until explicitly removed from Customer/Venue pages.
