# v0.1.68 – CustomerList Completed

## Summary

Completed the first full implementation of the Address Book CustomerList page. This version establishes the standard architecture and user experience that will be reused for ContactList and VenueList.

---

## Customer Management

Completed:

- Add Customer
- Edit Customer
- Duplicate Customer
- Delete Customer
- Active / Inactive support
- Search
- Active / Inactive / All filtering

CustomerList is now considered functionally complete for the current development phase.

---

## Contact Management within Customer

Completed the embedded Contact workflow.

Implemented:

- Add Contact from Customer
- Save Contact
- Save & New Contact
- Customer modal remains open while managing contacts
- Accordion behaviour corrected
- Contact selection retained correctly
- Previous stale contact data issue resolved

---

## Contact Selection Improvements

Implemented:

- Selected Contacts are displayed first in the multiselect.
- Remaining Contacts follow alphabetically.
- Contact option generation moved into the customerContact JSObject.
- Widget now simply calls:

```javascript
{{ customerContact.getContactOptions() }}
```

reducing widget-side logic.

---

## Customer List Improvements

CustomerList now displays linked Contact names.

Implemented:

- Contacts column added.
- Multiple linked contacts displayed as a comma-separated list.
- Full list visible using Appsmith tooltip on hover.

---

## Architecture

Further standardization completed.

General direction now established:

- JSObjects own business logic.
- Buttons call JSObject procedures.
- Widgets remain thin and primarily display data.

This pattern will be reused throughout the Address Book.

---

## Status

CustomerList development is complete for this phase.

Future improvements, if required, should come from shared enhancements discovered while implementing ContactList and VenueList rather than Customer-specific changes.
