## v.0.1.74 - Proposal Normalization

### Supabase
- Normalized Proposal document lifecycle.
- Finalized Proposal statuses:
  - Draft
  - Issued (user-facing: Sent)
  - Accepted
  - Declined
  - Ordered
  - Closed
- Direct Draft → Accepted/Declined/Ordered now internally issues the Proposal first.
- Enforced one Accepted/Ordered Proposal per Event.
- Previous Accepted/Ordered Proposal automatically returns to Issued.
- Added Proposal Draft save/update/delete normalization.
- Active remains independent of Proposal Status.
- Removed obsolete resolved_at field and rebuilt dependent views.
- Proposal backend normalized in preparation for Quotation integration.

### Appsmith
- Created Proposal selector section.
- Added Proposal list query filtered by current Event.
- Selector now displays Proposals for the selected Event only.
- Standardized selector layout.
- Agreed selector columns:
  - Reference #
  - Status
  - Sent
  - Active
- Standardized Proposal sorting:
  - Ordered first.
  - Then newest Sent date.
  - Drafts by Created date.
- Standardized date/time display:
  - YYYY-MMM-DD
  - YYYY-MMM-DD | HH:mm
- Standardized document identity:
  - Draft displays as "Draft n".
  - Official Proposal Number will replace Draft label after first Send/Issue.

### Architecture
- Confirmed Proposal remains Kitchen-owned.
- Confirmed Quotation remains Sales-owned.
- Confirmed Proposal → Quotation is the only workflow link between the two systems.
- Confirmed Proposal and Quotation will share the same document lifecycle and UI pattern.
- Confirmed official Proposal numbering will be client-wide, unique and assigned only upon first Send/Issue.
- Prefix and suffix will both be optional user-configurable Settings.
- Event-local Proposal numbering remains internal while Draft.
