Version: v0.1.72
Title: Quotation Normalization Foundation

Summary
-------
This milestone establishes the normalized architectural foundation for the Quotation module. The focus was on removing legacy assumptions carried over from the Excel application and earlier single-user workflow, replacing them with clear ownership boundaries between Kitchen (Events/Proposals) and Sales (Quotations).

Completed
---------
• Confirmed Proposal is a one-way handoff from Kitchen to Sales.
• Confirmed Kitchen and Sales operate as independent systems after Proposal issuance.
• Finalized Quotation lifecycle:
    - Draft
    - Issued
    - Accepted
    - Closed
• Confirmed Preview is an internal view only and does not affect status.
• Confirmed Issue automatically performs Save if a Draft does not yet exist.
• Confirmed Issued/Accepted quotations are immutable; modifications require Duplicate.
• Removed previous revision-based direction in favour of duplicate-to-edit workflow.
• Clarified ownership:
    - Proposal owns Proposal snapshot.
    - Quotation owns quotation content, pricing, menus, totals and terms.
    - Event owns deposits.
• Confirmed Event deposits remain live across all quotations for the same Event.
• Confirmed deposits are never stored as part of the quotation snapshot.
• Confirmed viewing, printing, exporting or emailing any quotation always displays the current Event deposits and recalculates the displayed balance.
• Confirmed quotation freeze applies only to quotation-owned data.
• Reviewed current Appsmith implementation and identified areas still based on the legacy quotation model.
• Began Appsmith normalization work to align with the new architecture.

Architectural Outcome
---------------------
The Quotation module now follows clear ownership rules with significantly fewer special cases and exceptions. The design is simpler, more deterministic and provides a consistent foundation for the remaining implementation work.

Next Phase
----------
• Normalize quotation database contracts.
• Complete Appsmith page initialization based on Proposal-first workflow.
• Implement Draft create/update logic.
• Implement Issue workflow.
• Implement Duplicate workflow.
