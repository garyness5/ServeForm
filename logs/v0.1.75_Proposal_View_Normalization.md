# v0.1.75 – Proposal View Normalization

## Summary
Completed the first phase of Proposal normalization by separating Proposal viewing from the live Event and wiring the Proposal snapshot data into the Events page.

---

## Database

### Proposal numbering
- Added Proposal document sequence support.
- Added optional suffix support.
- Proposal numbers are only assigned when a Proposal is issued.
- Drafts continue to use Draft 1, Draft 2, etc.
- Proposal numbers are unique and never reused.

### Proposal status
- Proposal status lifecycle finalized:
  - Draft
  - Issued
  - Accepted
  - Declined
  - Ordered
  - Closed

- Only one Proposal per Event may be Ordered/Accepted at any time.
- Previous Ordered Proposal automatically returns to Issued when another Proposal becomes Ordered.
- Sent date remains unchanged when status changes between Issued, Accepted and Ordered.

### Proposal snapshots
Verified Proposal snapshots load independently from Event data.

Verified:
- prop_items
- prop_menus
- vw_prop_items
- vw_prop_menus

---

Verified switching:

---

## Business Rules

Confirmed separation between Kitchen and Sales.

Kitchen:
- Guests + Extras = Production quantity.
- Kitchen Cost includes production extras.

Quotation:
- Receives contracted Guests only.
- Receives Kitchen line cost including production extras.
- Does not receive Extra Guest quantity.
